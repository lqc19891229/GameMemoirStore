# 房间系统六项完善工程清单

本分支用于安全落地第一批改动；尚未实现的功能不得标注为完成。
基线：Godot 4.6 / GDScript / Compatibility renderer。继续保留库存 UID、旧家具角色、交易存档和撤销/重做规则。

## 已提交的改动（需要 CI 与图形验收）

- [x] 配色预设从 9 种增加到 16 种，旧索引 0–8 及原颜色数据保持不变；场景浮动色板自动读取新增选项。
- [x] 家具与多选组支持 RGB/HEX 色彩选择，关闭拾色器时一次提交；使用专属高位标记在现有家具颜色整数字段保存，旧版色号原样保留，并支持撤销/重做。
- [x] `MemoirFurnitureSupportSurfaces`：校验局部表面锚点、检测物品占地是否落在表面内、转换到世界坐标，拒绝非法值、超界以及重名锚点。
- [x] 书架（4 层）、写字桌、边桌、两种茶几、矮架的脚本运行时提供显式承载面数据。已接入专用的手动陈列操作，原有地面放置仍保持默认行为。
- [x] 房间编辑模式增加“拍照”，在隐藏房间 HUD 后从当前渲染帧抓取 PNG，存入 `user://room_photos/`，并向玩家显示实际路径/错误。
- [x] 新增锚点、色板、购买/陈列/跟随/撤销/存档回归脚本，纳入房间专项 CI 工作流。
- [x] 新增陶瓷纪念杯和迷你设定集：通过现有商店付费购买，拥有独立库存 UID 和房间摆放场景；初版是程序化模型，正式 GLB 仍待制作。

- [ ] 支持完整的墙面装饰和照明：外墙和内墙的画框、首款可购买壁灯已接入，更多壁灯款式与复杂开口碰撞待扩展。

## 验证

通过 GitHub Actions `Room UI smoke checks` 对新增基础模块执行 Godot headless 用例。
还需要在本地 Godot 图形窗口人工检查色板弹层布局和 PNG 截图质量。
本分支已有“购买小摆件 → 地面临时摆放 → 选中点击陈列 → 支撑家具移动跟随 → 撤销与读档”的首个流程。仍缺少拖动式表面精细摆放、独立旋转、墙面挂装、批量陈列、成熟 GLB 模型及完整灯光和作品系统，不应视为六项全部完成。

**当前交互限制：** 两款小型收藏品从商店或目录开始放置后，鼠标移到桌面、书架时可直接贴面预览并确认；地面仍可放置。其他家具仍按原有地面流程。已陈列物品可拖动/旋转；尚未覆盖墙面、多个独立材质槽和更多小摆件。

## 自由装修原则（取代旧功能分区）

- 房间不再定义「游戏区 / 工作区 / 休息区」，也不提供阅读、游戏、休息场景灯光预设。
- 建造模式保留墙体、自由地板、逐格地板材质、外墙/内墙配色与门窗操作；不再提供功能区画笔、整区赋予用途、区域自动灯具和装修预设槽位。
- 灯具继续按单件控制开关与亮度，现有壁灯色温功能由独立 PR 处理，不依赖房间用途。
- 载入旧自定义户型时，将旧功能区的地板色转换为同位置的普通地板材质；手动绘制的地板色优先。旧功能区名称、区域灯光与装修方案存档槽位不再沿用。
- 使用真实内墙区隔出的物理房间、自由地板碰撞和连通性仍然存在，不等同于功能分区。
